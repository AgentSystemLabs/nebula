## Worktree views

The grid isn't the only view. With a session selected:

| Key | View |
|---|---|
| **`g`** | **Git diff.** Changed files down the left, the diff on the right, with a live fuzzy filter. On an open-PR row it shows that pull request's diff instead, fetched whole with `gh pr diff`. `Ctrl+r` marks a file reviewed ✓ and sinks it to the bottom — nebula-side bookkeeping only, no git state is touched — and every mark clears itself when HEAD moves or the file changes again, so what's left unticked is genuinely what you haven't read. `Ctrl+t` folds the file list into a directory tree and back — every directory open, a chain of directories that hold only each other shown as one row (`crates/nebula-tui/src`) — and the choice is remembered; in the tree `→`/`←` open and fold a directory, `Enter` or a click flips it, a directory's row lists what changed under it, and a directory wears the ✓ once every file under it has one. |
| **`f`** | **Find file.** Fuzzy finder over the worktree. `Enter` opens the file in an editor modal (vim by default; the `editor` setting or `NEBULA_EDITOR` picks another) — except a markdown file, which is read first: it opens as the rendered page in the file tabs below, where `Enter` is the editor and `m` shows the source — and `Ctrl+y` copies the path — ready to paste into an agent. The editor modal sits above every OVERLAY and is handed every key raw — vim owns `Esc` — so `Ctrl+q` is the only way out of it: one press kills the editor process and closes the modal, and the mouse is inert the whole time it is up. |
| **`F`** | **Find in files.** `git grep` into the same modal; `Enter` opens the hit at its line. |
| **`i`** | **GitHub issues.** The selected project's open issues, newest first down the left, the one under the cursor read on the right — number, title, author, labels, the description, and its comments once the cursor has rested on it for a moment (the `gh issue list` runs in the background once the cursor rests on the project, and again every couple of minutes while it stays selected, so the modal opens on rows already there; one `gh issue view` per issue you stop on). The list filters as you type, from the moment the modal is up: letters narrow the rows to the fuzzy matches of `#15 title`, best first with the cursor on the best and the matched letters lit (the count reads `2/14`), `↑`/`↓` (or `Ctrl+n`/`Ctrl+p`) walk the matches, and `Esc` clears the filter before a second `Esc` closes. So the verbs are chords, as in the diff viewer. `PgUp`/`PgDn`, `Ctrl+d`/`Ctrl+u` and `Shift+↑`/`Shift+↓` read (`Ctrl+u` kills the typed filter first, as in any line editor), `Ctrl+o` — or a click on the `↗ open in browser` button pinned right on the reading pane's frame — opens the issue in the browser, the footer saying where it went; `Ctrl+r` asks GitHub again. `Ctrl+c` leaves a comment on the issue: a multi-row box (`Shift+Enter` for a newline) whose `Enter` posts the text as you with `gh issue comment` and lands back on the row, the pane saying the comment is on its way until GitHub answers and the conversation is read again; `Esc`, or an empty box, lands back without posting, and a post `gh` refused brings the box back with your text. `Ctrl+e` edits the issue itself, in place: the reading pane becomes a form on its title and description (`Tab`, `↑`/`↓` or a click move between the two, `Shift+Enter` breaks a line in the description), `Enter` sends both to GitHub as one `gh issue edit` and puts the pane back reading the new text, `Esc` drops the draft; a save GitHub refuses keeps the form up with `gh`'s reason on it and your text intact. `Enter` opens the QUICK PROMPT *for that issue* and `Shift+Tab` picks one of your AGENT PRESETS for it — the box's own keys, and the same box either way, titled `Quick prompt · issue #15 …`, with `Tab` / `Shift+Tab` / `Ctrl+N` working as they do in any quick prompt. What that launch starts is an ISSUE SESSION: the issue's URL travels with the create and reaches the harness as context on every spawn and resume — Claude and Pi in the appended system prompt, Codex, Cursor, Muse and OpenCode at the top of their first prompt — so the agent knows which issue the session is for before it reads a word of your task. Send the box empty and the task is `Fix GitHub issue #15: <title>`; it launches on the project's root branch, and `Ctrl+N` inside it cuts a fresh worktree named `issue-15-<title-slug>` instead (the box starts on that fresh worktree with `New worktree` on under **Quick prompt** in Settings → Agents). |
| **`v`** | **GitHub pull requests.** The selected project's open pull requests down the left — the OPEN PRS group's rows, newest first with the drafts below, drafts listed even while the panel hides them — the one under the cursor read on the right as the pane reads it: state, checks, branches, the description, then the conversation once the cursor has rested on it (the rows are the list the OPEN PRS beat already keeps warm, so the modal opens on them at once; one older than thirty seconds is re-asked underneath). The list filters as you type, as the ISSUES MODAL's does: letters narrow the rows to the fuzzy matches of `#42 title`, `↑`/`↓` (or `Ctrl+n`/`Ctrl+p`) walk the matches, `Esc` clears the filter before a second `Esc` closes, and the verbs are chords. `PgUp`/`PgDn`, `Ctrl+d`/`Ctrl+u` and `Shift+↑`/`Shift+↓` read, `Ctrl+r` asks GitHub again. `Enter` opens the QUICK PROMPT for a PR SESSION on that pull request, `Shift+Tab` launches one of your AGENT PRESETS on it and `Tab` picks a harness and starts one bare — the box's own three keys, and the same launches the group row's `p`, `e` and `n` make, in the project's checkout of the PR's head branch. `Ctrl+c` comments on it and lands back on the row, `Ctrl+g` opens its diff, `Ctrl+o` — or a click on the `↗ open in browser` button pinned right on the reading pane's frame — opens it in the browser and marks it read on the way out, as `Shift+V` does from a card; `Esc` closes. |
| *(none — an agent opens it)* | **File tabs.** What `nebula open <file>…` raises when a session runs it — ask an agent to "open it" or "show me the file"; it never opens one unasked, and only text files — an image or any other binary is refused at the CLI, so the agent names the path instead. A modal with a tab strip like the SETTINGS OVERLAY's, one tab per file: `←`/`→`, `Tab`/`⇧Tab` and `1`-`9` switch tabs, the focused tab's file is previewed underneath with the TREE BROWSER's highlighting — a markdown file as a rendered page (headings, lists, fenced code, tables, links; `m` flips it to the source and back, and the choice holds across tabs) — and `Enter` runs the editor in that pane (the tabs stay put; `:q` lands back on the strip with the file re-read). `↓`/`j` from the strip drops into the preview, where `j`/`k`, `Ctrl+d`/`Ctrl+u`, `PgUp`/`PgDn` and `Home`/`End` scroll and `↑` off the top returns to the strip. This is the one OVERLAY where `Ctrl+q` is staged: from the editor or the preview it steps back to the tab strip, and only from the strip does it close; `Esc` backs out the same way. |
| **`b`** | **File tree browser.** Tree on the left, syntax-highlighted preview on the right (a markdown file as a rendered page; `Ctrl+r` flips it to the source and back), and an always-live filter that narrows the tree to matching files and the directories holding them. `→` expands a directory and `←` collapses it; `Enter` folds or unfolds a directory, and on a file it loads the file into the *preview pane* rather than the floating editor modal that `f` and `F` open — the tree stays where it is. The preview takes the DIFF VIEWER's scroll keys: `Ctrl+d`/`Ctrl+u` half pages (`Ctrl+u` only while the filter is empty — with text typed it is the LINE EDITOR's kill-to-start), `Shift+↑`/`Shift+↓` a line, `PgUp`/`PgDn` a page, `Home`/`End` the ends. `Ctrl+y` copies the selected path, and dragging the tree/preview border resizes the tree side. |

## Full keymap

| Context | Key | Action |
|---|---|---|
| The grid | `/` | fuzzy jump across every live project, worktree and session on the machine (`Ctrl+n/p` move, `Ctrl+o` opens the hit, `Ctrl+f` just lands the selection on it). **Archived sessions are never rows here**, whatever the SESSIONS panel's `A` toggle shows and however exactly you type the name: an archived session's PTY is released, so there is nothing to jump to — `.` / `,` skip them for the same reason. The list is flat — one row per thing, nothing folded under anything: each reads `project/name`, the project it lives in dim, then its own name (a session's title, a worktree's branch, a pull request's `#42 title`), with a dim `23m ago` pinned right. Until you type it is a recent sessions list: the sessions and nothing else — no project or worktree rows in the way — in attention order, the ones waiting on you first, then the running ones, then the unread finishes, then the rest by last interaction, with the cursor on the top row, so `/` `Enter` is the fastest way back to what needs you or to what you last ran. `Enter` on a session that NEEDS FEEDBACK — the red row — attaches and focuses the TERMINAL PANE whatever `palette_enter_attaches` says, since the only thing to do with a jump to a question is answer it; `Ctrl+f` is still the way to only land on it. Typing reaches every row, projects and worktrees too, on lines of their own in that same order; the query runs over each row's full `project/branch/session` path, so a project's or branch's name narrows to what is under it, even the parts the row does not draw, and every visible row counts toward the `(hits/total)`. Every open pull request nebula has listed is a row too, `↗ project/#42 title`, searchable by number or title (`#` lists them all), and badged `draft` or `ready for review` after the title — the same states the sidebar's PR rows wear, spelled out here where there is room (`ready for review` is an open pull request that is not a draft; it says nothing about approvals, checks or mergeability), or `merge conflicts` / `checks failing` in red, the row red with it, when GitHub says the pull request cannot merge as it stands — so a draft is told from a finished one, and a blocked one from either, before it is picked, by the word and not only by its color; the badge follows the next `gh pr list` answer, so a draft marked ready flips under an open palette. `Enter` on one selects its project, unfolds the OPEN PRS group and lands the WORKTREES cursor on the row, so the PR PREVIEW reads it in the pane — no checkout or session of its own needed. `Ctrl+o` on it is the explicit way out to the browser, as is `Enter` on the row once landed |
| The grid | `.` / `,` | next / previous session in that same attention order, with no modal: one press lands on the next session waiting on you (then the running ones, then the unread finishes, then the rest by last interaction), wrapping at both ends. It is `/` `Enter` without the typing — a session in another project selects that project, its worktree and its row, and `palette_enter_attaches` decides whether the pane is attached and focused or only selected and previewed — a session that NEEDS FEEDBACK is attached and focused either way, as it is under `/` `Enter`. Landing on an UNSEEN finish reads it, so the DONE BADGE counts down as you cycle. With nothing red or blue it still walks the running sessions, then everything else; with no sessions anywhere the footer says so |
| The grid | `o` | open a project: a folder with a git repository in it, from any focus. The prompt starts on the folder nebula was started in — its parent listed, the folder itself highlighted — so `Enter` opens it; started anywhere else it starts at `~/`. A folder that already is a project (its root, a checkout of it, or a folder inside either) opens that project rather than adding it twice. On the first-run splash `n` opens the same prompt, and `Enter` opens the folder nebula was started in outright |
| Open project | type + `Tab`, `↓↑` / `→` / `←` | browse for the repo: type to filter (bash-style Tab completion), arrows pick a directory, `→` steps in, `←` steps up, `Enter` opens the highlighted (or typed) path; `●` marks git repos |
| The grid, on a root-branch card | `c` | the BRANCH SWITCHER: move the project's ROOT WORKTREE onto another branch — the checkout the card under the cursor runs in (a linked worktree only says why not: a worktree stays on the branch it was cut for), or the project's root with no card selected. It lists the current branch first, then the other local branches newest commit first, then the remote branches no local branch shadows, newest first — each with its last commit's subject and age — and `Enter` switches (a remote branch becomes a local branch tracking it). Type to filter, fuzzily, as in `/`; `↑`/`↓` or `Ctrl+n`/`Ctrl+p` move. Opening it starts one background `git fetch --all` (at most once a minute per checkout; `Ctrl+r` fetches again now) and the list follows when it lands. With nothing matching, `Enter` creates the typed branch off the current one and switches to it, changes and all (a name that starts with a remote's, like `origin/x`, is refused — it would shadow the remote branch). A checkout with uncommitted changes stops and asks how they travel: `s` stashes them under an entry named `nebula: <from> before switching to <to>` (if git refuses the switch, or stops part-way — a missing git-lfs does that — the files it wrote are undone and that entry is applied straight back), `b` brings them along (git's own switch, refused when they collide with the target), `c` commits everything first — untracked files too — after asking for the message (refused on a detached HEAD, where the commit would belong to no branch), and `d` discards changes to tracked files on a second `d`, unstaging first so untracked and newly added files stay; if the changes moved since the prompt opened — a new change, or another edit to a file already listed — it asks again. `Esc` backs out one step at a time. Nothing switches mid-merge, mid-rebase or with unresolved conflicts, and a git repository nested in the checkout (a `.claude/worktrees/…` checkout) is neither counted as a change nor committed. A branch another worktree has checked out is listed but refused, since git keeps a branch in one checkout. One switch runs per checkout: `Esc` while git works hides the modal and `c` brings it back, and an answer that lands while it is hidden is said in the footer. A switch that stops part-way puts back only files byte-identical to the target branch's, so nothing anyone wrote is touched; whatever it could not undo, it names. Sessions running in the checkout keep running and see its files change. The root row's right-click menu has it as **Switch branch…**; rebindable as `switch_branch` |
| The grid | `Shift+Enter` / `Shift+O` / `Alt+Enter` | open the selected worktree: fires its OPEN COMMAND once — **Open command** on the SETTINGS OVERLAY's Project tab (`s`) when it is set, else the `open` command from the checkout's `.nebula.json` — `open http://localhost:3000`, say — through `$SHELL -c` in that checkout, from the TUI, so it opens things on the machine you are sitting at; its output is discarded. Neither set, and the footer names both places. The worktree is the one under the Worktrees cursor, from whichever panel you press it (a PROJECT OPEN PRS row has no checkout to open). `Shift+Enter` needs the KITTY PROTOCOL to arrive as a key of its own: Ghostty and kitty send it; Terminal.app sends a plain `Enter`, which drills into Sessions instead, and tmux flattens a shifted Enter to a plain one on its way to the pane whatever `extended-keys` says. So two keys are bound beside it: `Shift+O`, which every terminal delivers, and `Alt+Enter` — the `ESC` `CR` that Claude Code's `/terminal-setup` makes VS Code's terminal send for Shift+Enter, and that Option+Enter sends on a Mac whose terminal treats Option as Meta — which tmux passes through untouched. Terminal.app can be taught the real key instead: Settings → Profiles → Keyboard, add `⇧↩` with the action *Send Text* and the text `\033[13;2u`. The Worktrees context menu (`m`) has **Open** too |
| The grid | `Shift+R` | refresh the pull requests now: the project's OPEN PRS list, the selected worktree's own PR ROW, and the description and conversation of the pull request the pane is reading are all asked of `gh` again at once — past the 15-second beat and the few-second floor a focus event respects — with the reader's scroll kept. `refreshing pull requests…` in the footer says it was heard; the rows repaint as the answers land. Its own key, not a meaning `r` takes on: it acts on the selected project and worktree, which every panel has, so it works from any row — `r` stays rename / edit everywhere but a checkout in the Worktrees panel, where it runs the project |
| The grid | `i` | GitHub issues: the ISSUES MODAL for the selected project (above) — read an issue, type to filter the list by `#15 title`, `Enter` prompts an agent on it, `Shift+Tab` launches an AGENT PRESET on it, `Ctrl+c` leaves a comment on it, `Ctrl+e` edits its title and description, `Ctrl+o` or the pane's `↗ open in browser` button opens it in the browser, `Ctrl+r` refreshes |
| The grid | `v` | GitHub pull requests: the PULL REQUESTS MODAL for the selected project (above) — read a pull request, type to filter the list by `#42 title`, `Enter` prompts a PR SESSION on it, `Shift+Tab` launches an AGENT PRESET on it, `Tab` picks a harness, `Ctrl+c` comments, `Ctrl+g` opens its diff, `Ctrl+o` or the pane's `↗ open in browser` button opens it in the browser, `Ctrl+r` refreshes |
| New worktree | type a sentence, or `Enter` on the empty prompt | the branch name is slugified (`fix login redirect` → `fix-login-redirect`); empty takes a random `<adj>-<noun>-<verb>`. The branch starts at the freshly fetched `origin/HEAD` (normally `origin/main`), untracked — never at the root checkout's HEAD; with no `origin`, or a fetch that fails, it falls back to HEAD. **Worktree base branch** (Settings → General; `worktree_base_branch` in CONFIG.JSON) names another start — `master`, `develop` — resolved the same way: origin's fetched copy first, the local branch of that name otherwise, and `origin/HEAD` again in a repo that has neither |
| The grid | `n` | new session: pick the harness (`→` drills into its model and effort, `Enter` takes your defaults) and it starts — no name or task box follows. The launch drops you into its pane, you type the agent's first prompt in the CLI, and the session titles itself from it. To start an agent on a task typed up front, use `p` (below). A shell terminal is `t` |
| The grid (a card) | `Ctrl+d` / `Ctrl+u` | half a panel down / up, the Worktrees rule on this column: the cursor jumps by half the pill rows the column has room for — live sessions, terminals, the PR ROW and the `ARCHIVED` group's rows as one list — stopping at the first and last row, with the list scrolling after it so the row landed on is in view and the pane previewing what it lands on. The jump is sized by pills, so RECENT PROMPTS lines under live rows are not billed: over them it moves a little more than half a panel, over the archived rows it is for exactly half. Same rebindable actions, `half_page_down` / `half_page_up` |
| New session picker (Claude) | `Tab` | toggle Claude Cloud; `Enter` then opens Cloud's own wrapped task prompt (`Shift+Enter` or `Ctrl+J` inserts a line) — the one picker row that asks before it launches, a cloud session being nothing without its task |
| Quick prompt's harness picker (Claude) | `Tab` | the same Claude Cloud toggle, in the picker `Tab` opens from the quick prompt: `Enter` hands the box back as a cloud one — `harness claude · cloud`, **Claude Cloud** in its title — with your text kept, and the box's `Enter` launches `claude --cloud=<task>` on what you typed. Not offered in a box for an issue or a pull request, which Claude Cloud cannot take |
| New session picker (any row) | `?` or `s` | open Settings → Agents parked on the highlighted harness's section, where its Enabled switch and default model and effort live (`s` types in the model/effort submenus instead, where the filter owns letters) |
| The grid (a cloud card) | `Enter`, `m` | `Enter` — or a click on the link in the CLOUD SESSION PANEL — opens the session's page in the browser; the `m` menu offers **Open in browser** and **Send to cloud session**, which queues a message on it. No **Attach** or **Restart**: the agent runs in the cloud, not in a terminal here |
| The grid (a card) | `Space` | **follow-up prompt, in the card itself.** The selected session's card expands in place into a small box — no modal over the screen — and what you type there goes to the agent already running in that session as its next turn: `Enter` sends it and folds the card back up, `Shift+Enter` / `Option+Enter` / `Ctrl+J` break a line, `Esc` folds without sending. Every card below it in the column moves down by what the box took, and off the bottom if the column runs out — the column scrolls to keep the box you are typing into on screen. While the box is open it owns the keyboard, so the panel's own letters (`a`, `d`, `r`…) are just letters; `Tab` still walks to the next panel and leaves the card expanded behind it. Each card carries the toggle it answers to: a `▸` at the end of its name row that a click expands, and a `▾` that a click folds — the same thing the `m` menu's **Follow-up prompt** row does. Only a live local agent has one: an archived session, a Claude Cloud row (whose `m` menu queues a message instead), a terminal and a pull request row have nothing to follow up on. A session whose CLI is not up is booted first and the box kept as it is, so nothing is typed into a process that is still starting — press `Enter` again once it is. With the LAUNCHER VIEW on, the same `Space` opens it as a small modal over the grid instead — see below. Rebindable as `follow_up` |
| The grid | `r`, `a`, `u`, `d`, `A` | rename, archive, unarchive, delete, toggle archived. `Delete` and `Backspace` are bound alongside `d` and do the same thing, here and everywhere else `d` deletes a row (a project, a worktree) — and `a` and the row menu's Archive ask first, in the CONFIRM DIALOG `d` goes behind (`Enter` or `y` archives, `Esc` or `n` keeps the session), so typing aimed at an agent that lands on this panel archives nothing; the dialog says what makes saying yes cheap: `u` brings the session back. On the PR ROW, which has nothing to rename, `r` only says so; `Shift+R` refreshes the pull requests (above). **A held `a` opens one dialog** and archives nothing by itself: its repeats land on the dialog, where `a` is nothing. **A held `u` unarchives one card**, however long it is held: on a terminal with the kitty keyboard protocol (Ghostty, kitty, WezTerm, foot) nebula watches the key until it comes up, swallowing the repeats the terminal sends meanwhile, and the next card needs the key pressed again; a terminal without it (Terminal.app, `nebula browser`, tmux) reports a held key as one press after another, and there a long hold still walks the row |
| The grid (a card) | `e` | agent presets: saved launch definitions (harness, model, effort, text on the side of the task the form's **Text** row names — a prefix, a postfix or both; a new preset starts on `prefix` alone unless **Preset text** in Settings → Sessions says otherwise — and whether to ask for a task). The launch lands in the selected worktree — the one whose sessions you are in, or the one under the Worktrees cursor. `Enter` asks for an optional task and starts the agent with prefix + task + postfix as its first prompt — sent empty, the prefix and postfix go alone — or, for a preset whose **Task** row is `skip`, launches at once without asking. Type to find a preset by name — letters narrow the rows to the fuzzy matches, the cursor on the best, the query in the title (`Agent presets ⌕ rev`); `↑`/`↓` (or `Ctrl+n`/`Ctrl+p`) move, `Backspace` widens, and `Esc` clears the letters before it closes. Because letters type, the verbs are chords: `Ctrl+a` / `Ctrl+e` / `Ctrl+d` create, edit, delete (`Delete` deletes too). On a PROJECT OPEN PRS row of the Worktrees panel the same key is a picker that launches the preset as a PR SESSION on that pull request (see that row above) |
| The grid | `p` | quick prompt: a wrapped, multi-row task box (`Shift+Enter`, `Option+Enter` or `Ctrl+J` inserts a line and `↑`/`↓` walk the rows as they wrap, as in Claude Code's own prompt — the keys for getting around a long prompt are under *Any multi-row box* below; `Esc` closes the box, `Enter` launches) that starts a new agent in the checkout under the cursor — the worktree whose band is selected, or the one the grid is inside — with what you typed as its first prompt — no picker. Which CLI it launches is the `Agent` row under **Quick prompt** in Settings → Agents, run with that harness's own default model and effort; the session titles itself from the prompt. For one launch only, `Tab` picks a different harness (`→` drills into its model and effort, same as the new-session picker) and `Shift+Tab` picks one of your saved agent presets — adopting its harness, model, effort and prefix/postfix wrapping; sent empty with a preset on, the box launches on the prefix and postfix alone, and a `skip`-task preset picked over an empty box launches right away. Either picker hands the box back with your text intact, on `Esc` too. The launch stays out of your way: the new session's row is selected and shown in the pane, but focus stays on the panel you fired from — turn on `Focus` under **Quick prompt** in Settings → Agents to drop straight into its terminal instead. The box launches in the checkout under the cursor by default — the worktree whose band the cursor is on, or the one the grid is inside, the new session starting beside the ones already running there (more work in one session's own conversation is its follow-up, `Space`) — and on the project's root branch once `Esc` has let the aim go; turn on `New worktree` under **Quick prompt** in Settings → Agents to have every new box cut a fresh worktree first — a random branch off the fetched `origin/HEAD`, or the **Worktree base branch** setting — moving the cursor onto the new row. On an open pull request's row it is a PR SESSION in the pull request's own checkout instead (above, under the `OPEN PRS` row). `Ctrl+N` inside the box flips between the two for this one launch only — the next box starts from the setting again: the row under the title says which — a quiet `worktree: main` with `[ ] new worktree` unticked, or a filled `NEW WORKTREE` chip naming the branch to be cut with `[✓] new worktree` ticked and the whole frame turned green — and the text and caret stay put across the flip. `Enter` on the box empty starts the session all the same — the harness, model and effort the title names, with no first prompt: you type it in the CLI, as after `n` (a Claude Cloud box, which needs its task, closes instead). Closing the box does not throw the prompt away: `Esc`, a click outside it and `^q` park what you typed, and the next `p` opens on it — aimed the same way, the box comes back whole, the `Tab` harness or `Shift+Tab` preset you had picked included; aimed somewhere else, your text comes back into that box's own launch. One draft is kept, in memory only, and the box that takes it back is the last place it can be lost from: clear it there and close it and it is gone |
| The grid | `Shift+D` | delete every row of the focused panel (confirm lists the casualties) |
| The grid | `g` | git diff for the selected worktree: filter, `↑↓` files, `Shift+↑↓`/`PgUp/PgDn`/`Ctrl+d/u`/`Home`/`End` scroll, `Ctrl+r` marks a file reviewed ✓, `Ctrl+t` flips the file list between flat paths and a directory tree (`←`/`→` fold, `Enter` flips a directory). `Ctrl+u` scrolls only while the filter is empty — with something typed it is the LINE EDITOR's kill-to-start |
| The grid | `Shift+G` | open the selected repo's page on its git host — the `origin` remote (`git@github.com:o/r.git`, `ssh://`, `https://`) turned into a browsable URL, credentials stripped |
| The grid (a card) | `Shift+V` | open the card's pull request in the browser — the `#42 title` line under its name, the pull request on the branch its session runs in — without stepping into the session or opening the PULL REQUESTS MODAL. `v` lists the project's pull requests in nebula; `Shift+V` goes to GitHub. It is marked read on the way out, as when it opens from anywhere else. A card with no pull request yet says so and names its branch (`Shift+R` asks GitHub again); with no card selected (after `Esc`) nothing opens. A click on that `#42 title` line, on any card, does the same — the cursor lands on the card first — and the line is underlined while the pointer rests on it, the way the header's tabs are. ## The grid

nebula's whole screen is a GRID of cards (see [Sessions](sessions.md#the-grid)): the sessions and
terminals of the project whose PROJECT TAB is lit in the header, grouped into a BAND per checkout —
a titled rule over one row of cards — with a pane down the right of them that reads the card under
the cursor. `j`/`k` walk the bands, `Enter` opens one (the grid is then that checkout's cards alone,
walked with `h`/`j`/`k`/`l`) and `Esc` backs out. There is no level above it — the tabs, the `+` in front of them, a digit and a
`/` jump are how you get to another project, and each of them lands on that project's sessions.
These are the keys of the grid itself:

| Where | Key | Action |

The last row, `+ open a folder…`, is the open-project prompt `o` opens, for a folder that is not a project yet. The list takes **type-ahead**: letters narrow the rows to what they fuzzy-match, best first, so a name and `Enter` is the whole of finding a project; `↑`/`↓` move (not `j`/`k`, which are letters here), Backspace widens, and a letter nothing matches is refused so the list never empties. `Esc` clears the query before it closes the list; a click off the list, or picking the name already ticked, leaves everything where it was. A tab's name and the `+` underline while the pointer rests on them, and a tab's `×` turns red — a word says nothing about being clickable, so that is the row's sign that it is a button |
| The grid | `p` / `n` | the box again, aimed at the project under the cursor and at the checkout the cursor is on — the worktree whose band is selected, or the one the grid is inside; its ROOT BRANCH with nothing selected — or at a fresh worktree with `New worktree` on under **Quick prompt** in Settings → Agents. Which of the worktree's cards is selected does not matter, only the worktree: more work in one session's own conversation is its follow-up (`Space`). `^P` in the box re-aims it at any project on the machine |
| The grid | `Shift+A` | **the ARCHIVED VIEW.** The same grid, of the project's archived sessions instead of its live ones — the header counts them under their own word — so `u` unarchives the card under the cursor where it stands and `d` deletes it. `Shift+A` again comes back to the live sessions. The two lists never mix: there is no ARCHIVED group to fold, only the other grid. `Enter` on an archived card says to unarchive it first — its session was reaped when it was archived, so there is nothing to read. An archived card is drawn as the live card put away: square frame (`┌` against a live `╭`), a square `▪` where the STATUS DOT was, the name muted and unbolded, the SCOPE COLOR and the PR's own colors off, and the badge counting from when it was archived (`2h ago`) rather than from its last turn — so which grid is up reads without the header, and without color at all |

Every other key in the table above acts on the card under the cursor — at the band level, the card
the pane reads (`a`, `d`, `g`, `m`, `/`, `s`, `?`, `q`). `^P` in the box is the way to another project without leaving this one: it aims the
box at any project on the machine without taking you there, so Enter starts that session in the
background and leaves the screen on the work in front of you.

## Chips and readouts

Two strips report state without being asked. The TERMINAL PANE's header shows one chip at a
time — the first of these that applies, so a scrolled-back exited session reads `exited`:

| Chip | What it is telling you |
|---|---|
| `exited` (red) | the session's process is gone. Keys stop reaching it — `Esc`, `Enter` and `q` leave the lock and everything else falls through to panel navigation — and the next attach is what respawns it |
| `scroll N` (yellow) | you are N lines back in the scrollback rather than at the live edge. Typing anything, or scrolling back down to the bottom, clears it |
| `starting…` (dim) | nothing has come off the PTY yet: the session was reaped while you were elsewhere and its CLI is booting now. The blank grid on its own reads as a hang, so the chip says otherwise |
| `INPUT` (accent) | the pane is locked and every key is going to the PTY — where `Enter`, the forward walk and a double tap of `l`/`→` all leave you. The panels' pane only: the pane under the LAUNCHER VIEW's grid keeps that corner for its close button, and its accent rule says the keys are in there |

The FOOTER carries the rest, left to right:

| Readout | What it is telling you |
|---|---|
| `nebula vX.Y.Z` at the far left | which nebula this is — the same string `nebula --version` prints, and the one thing on the bar that never moves with the cursor. It costs the key hints ~18 columns and steps aside only for a flash message that would not otherwise fit |
| `⇡ v0.22.0` right after it, in the warning color | a newer nebula is published on GitHub — the nudge to run `nebula upgrade`. Checked once at start and hourly after with one `curl` to the release page's redirect (no `gh` token, no API quota); it says nothing while it can't ask, and `NEBULA_UPDATE_CHECK_SECS=0` turns the check off |
| `✗ disconnected` | this client has lost the DAEMON. It is the client-to-daemon link and nothing else — a session's own health is its `●` STATUS DOT, and a hollow `○` is an agent the daemon restarted out from under. A healthy connection says nothing at all: the bar reports the link only when something is wrong |
| `2 agents · 1 term · 3 warm · 412 MB` at the right edge | live counts and nebula's whole memory footprint — this TUI, the DAEMON and every session's process subtree summed — re-read every 5 seconds while no modal is up. Prewarm spares are counted apart as `warm` so the agent figure matches the sidebar, and the whole readout is blank until the first reading lands. It is a button: the pointer on it underlines it, and a click opens the memory modal, the same one `Shift+M` opens |
| `j - Move down` on the blank row above the bar, far left | the KEY COMBO DISPLAY (Settings → Experimental, `show_key_combos`), off by default: the key you just pressed in a keycap and what it did, for anyone watching a screen share — vim's `showcmd`. A double tap reads as one combo (`l l - Enter pane`), an unbound key bare, and it clears itself three seconds after the press. Keys typed into a LOCKED PANE never show (only the hatch out and the pane fold do), nor does anything typed into a modal's text field — in a modal only `Esc`, `Enter`, `Tab`, the arrows and `^`/`⌥` chords show, bare |

## Mouse

The mouse is another way to press the keys, never a second set of behaviors: a click on a row is
the arrow keys landing there, a click on a row of a picking list (a menu, the `/` palette, the file
finder, the agent presets, the ssh hosts) is `Enter` on that row, a second click on a row you are
already on — a session, a checkout, a pull request, a settings row — is `Enter` on it, a right-click
is a click followed by `m`, and a click into the terminal pane is `Enter` on the pane. So a markdown
file clicked in the file finder opens read-first in the file tabs as `Enter` opens it, a preset clicked
in a pull request's preset picker starts the PR SESSION `Enter` starts, and a right-click on another
checkout brings its session into the pane as `↑/↓` onto it would. Double-click in the terminal selects
a word, `⌥`-click opens the URL or `file:line` under the cursor (browser / editor modal; a `.md` opens
read-first in the file tabs, `Enter` there for the editor), and dragging a
visible panel border resizes it. Hidden panels keep their last width for the next time they are shown.
A click on a project or worktree row (like `↑/↓` onto it) brings back the session it was last on, or
its top row — the most recently interacted session — when nothing is remembered yet or that session
is gone; only a worktree with nothing to show blanks the pane.
A click on the pull request on a band's rule (`↗ #42 title`) is `Shift+V` on that checkout: the cursor
lands on the band (unless the grid is already on that checkout, inside it or not) and the pull request
opens in the browser; the link is underlined while the pointer rests on it, and a right-click on it is
the band's right-click.
A click outside any modal (help, settings, a confirm, a prompt, the pickers) dismisses it, and
focuses the panel it landed on — only focuses it: the click was spent closing the modal, so it moves
no cursor, previews no session and switches no project. Landing in the terminal pane takes the
input lock the way a click there always does. That is not always the same thing as `Esc`:
the DIFF VIEWER, the PALETTE, the FILE FINDER, its grep view, the TREE BROWSER and the BRANCH SWITCHER all stage `Esc` —
the first press clears the typed filter and only a second one closes — where a click outside closes
them outright, first press. The CONTEXT MENU splits the same way: `Esc` backs out one submenu level
at a time, a click outside takes the whole menu. The rest (a CONFIRM DIALOG, a prompt, the agent
presets list, the preset editor) really do run their own `Esc`, side effects and landing included.
The wheel scrolls whatever the pointer is over — the GRID included, whose cards the keys walk and the wheel
only moves under them: it moves their lists without touching the selection, and the PR PREVIEW scrolls three
lines a notch while a cursor is resting on a pull request. Text selection: hold `Shift` while dragging (mouse capture bypass —
same as tmux).

A program that asked for the mouse itself — Claude Code's fullscreen renderer, vim with `mouse=a`,
htop, tmux with its mouse on — gets the left button the way a plain terminal hands it over: the
press, the drag and the release all reach it, and its own selection does the copying. Claude Code's
knows that its `/diff` panel sits beside the conversation; a screen-row copy of nebula's took the
panel along with the reply. nebula's own drag-select is for everything that never asked — a shell,
Claude Code's classic renderer — and `Shift`-drag selects through the terminal either way. A copy
the program sends its terminal as an OSC 52 write (Claude Code over `nebula ssh`, vim's OSC 52
clipboard, tmux with `set-clipboard` on) is passed on to the terminal you are sitting at, the route
nebula's own copy takes on a remote host.

A drag-select ends when the button comes up and not before: the wheel, the agent printing on, a
resize, even a replay that rebuilds the screen all leave a drag in progress where it is, since the
selection is pinned to the text rather than to screen rows. Drag past the pane's top or bottom edge
— onto the rule above it or the footer below — and the history scrolls under the pointer until it
comes back inside, a line per tick for each row past the edge, so a copy can run longer than the
pane is tall; the release copies every row the drag crossed, on screen or not.

A host terminal can forget that it was asked for the mouse — iTerm2's Session ▸ Reset (`⌘R`) does,
and so does a stray full reset — after which every click goes to the terminal and the wheel scrolls
its own scrollback instead of the pane. nebula asks for the mouse (and bracketed paste, focus reports
and the kitty keyboard flags) again every two seconds — never in the middle of a drag — so the mouse
comes back on its own; resizing the window also re-enters the alternate screen and repaints every cell.
