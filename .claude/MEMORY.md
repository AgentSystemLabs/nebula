# Nebula Memory — index

The MEMORY LOG's index: one line per task, newest first, written by the NEBULA-MEMORY SKILL. Each line
names the entry's date, title, the TERMS and files it is about, and its gotcha count, and links the
entry file under `.claude/memory/entries/` that holds the full **Asked / Did / Gotchas**. Read this file
and `.claude/memory/gotchas.md` (the standing gotchas) in full before every task; open the entries whose
line matches what you are working on — the RECALL HOOK (`.claude/hooks/recall.py`) injects the matching
ones automatically as `[nebula recall] …`. Lines that fall off the bottom of the 200-line cap move to
`.claude/memory/archive.md`, which the hook still searches. `make memory-check` enforces the caps and
the index ↔ entries agreement. Format, caps and pruning: `.claude/skills/nebula-memory/SKILL.md`.

Line shape: `- DATE · [Title](memory/entries/DATE-slug.md) · TERMS: A; B · files: a.rs; b.rs · gotchas: N`

> **Provenance.** Entries dated 2026-08-04 through 2026-08-24 are a backfill reconstructed on 2026-08-24
> from 152 session transcripts, `git log` and verified notes; later entries are first-hand. The monolithic
> `.claude/MEMORY.md` was split into this index plus per-entry files on 2026-08-28.
