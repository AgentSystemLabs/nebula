**Gotchas:**
- `claude -p --output-format stream-json --verbose` repeats a *first-chunk* usage snapshot on every record of one API response (`output_tokens` ≈ 7 on all of them, same `message.id`): per-call `input_tokens` / `cache_read_input_tokens` / `cache_creation_input_tokens` are exact (their sums matched the final `result` usage to the token and reproduce the bill at $10 / $0.25 / $20 for the 1-hour cache write / $50 per Mtok), but output totals exist only in the final `result` record — a per-call output timeline is not recoverable.
- The auto-mode classifier blocks `--dangerously-skip-permissions` in a Bash command, blocks writing a wrapper script that contains it, and blocks running an opaque `run_arm.sh` at all; the identical `claude -p … --permission-mode auto --permission-prompts none` inline is allowed — and it is the mode the user's own sessions run under, so it is the fairer replica anyway.
- A `-p` run loads the project skills, `CLAUDE.md` and the RECALL HOOK like an interactive session (a haiku probe listed 33 skills and confirmed the `[nebula recall]` injection, $0.04) — verify this before spending $20 on a run that hinges on it.
- Background Bash tasks and a Monitor do not survive a Claude Code session restart ("no completion record was found"); the `nohup`'d runs did. Write `.exit` / `.finished` / `.wall_seconds` markers from the wrapper and poll the files, and `rm` the markers a `pkill`ed first launch left — a fresh Monitor read them as `ARM A FINISHED exit=143` while the real run was alive.
- The SKILL AUDIT HOOK's Stop continuation is the *last* assistant text of a headless run, so `result.result` is the audit note, not the task summary; the real closing summary is the last `==== OVERVIEW ====` block in the stream.
- `git clone --depth 1 <local path>` ignores `--depth` (git warns and clones full history); the `file://` URL form honours it (`git rev-list --count HEAD` = 1).
- The GUARD HOOK's `piped-cargo-hides-its-exit-code` rule fires on a pre-warm `cargo build … | tail -3` too — redirect to a log and `echo $?`; and zsh does not word-split `set -- $pair` inside `for pair in "a-with-skills a"`, so a two-field loop variable needs `read -r d l <<< "$pair"` or two arrays.
- Both arms edited mostly through Bash (`sed -i`, python heredocs) rather than Edit/Write — the auto-mode system text asks for that — so "files edited" must be counted from the diff, not from Edit/Write tool calls (A: 10 Writes, 4 of them `/tmp` edit scripts; B: 1 Write for a 20-file change).
