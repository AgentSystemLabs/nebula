# Claude Code Has No Glossary Autocomplete — Only Prefix Pickers, And `fileSuggestion` Is The One Hook — 2026-08-28

**Asked:** "find if there is a way to configure the claude code session that nebula creates to allow a user to get some type of auto complete where when they type in a term it will preview options they could tab complete"

**Did:** (Extended the same day — "try to add it for me".) Built the `@` TERMS picker: `.claude/hooks/terms-suggest.py` answers `fileSuggestion` with the TERMS whose name or alias (Also-called cell + Alias index, Retired left out) contains the query, prefix matches first, then `git ls-files -co --exclude-standard` paths (basename hits first), 15 total, ~25 ms; wired as `"fileSuggestion"` in `.claude/settings.json`. Live-verified from the repo root under tmux: `@works` lists WORKSPACE / WORKSPACES BAR / …, `@terms-sugg` lists the script, and on submit the TERM stays literal text while the file path attaches (Claude read the 110-line script). Research before that: Verified against `claude` 2.1.251 (binary strings) and the docs at `code.claude.com/docs/en/{interactive-mode,settings-reference,keybindings,skills}.md`. Claude Code's input completes only after a prefix: `/` (skills, `.claude/commands`, MCP prompts, fuzzy), `@` (file paths + live sessions), `:` (emoji, `emojiCompletionEnabled`), `!` (shell paths), plus `Ctrl+R` history and the ghost-text prompt suggestion after each turn (`promptSuggestionEnabled` / `CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION` / `--prompt-suggestions`, Tab or → accepts). No mid-word / glossary typeahead exists. The one pluggable source is the `fileSuggestion` setting (`{"type":"command","command":"…"}`, scope "Any file" so it fits the repo's `.claude/settings.json`): the command gets `{"query":"…"}` on stdin, prints newline-separated candidates, ≤15 shown, 5 s timeout, hook env incl. `CLAUDE_PROJECT_DIR`. That is the route to a TERMS picker (`@WORKS<Tab>`); nothing in `agent_spawn_command_with` needs to change for it. **Live-tested** (same day, `claude --settings` under tmux, prototype in the session scratchpad `attest/`): a `fileSuggestion` script that greps the `| **TERM** |` rows of `TERMS.md` fills the `@` popup with TERMS, Tab accepts one, a multi-word candidate is inserted quoted (`@"DEFAULT WORKSPACE"`, a single word as `@AGENT`), and on submit the `UserPromptSubmit` payload and the model both receive it as literal text — no file lookup, no error, nothing dropped.

**Gotchas:**
- `terms-suggest.py` must keep emitting file paths — `fileSuggestion` replaces the built-in `@` file completion wholesale, so a TERMS-only script silently takes file mentions away from every AGENT on this checkout.
- A non-path `@` candidate passes through as plain text (`@"DEFAULT WORKSPACE"` — quoted when it has spaces), so the RECALL HOOK / model see the TERM's words; nothing tries to read it as a file. The script is called once per input change with the text after `@` as `query` (the hook JSON also carries `session_id`, `transcript_path`, `cwd`).
- `argument-hint` in SKILL.md frontmatter is documented but rejected by the frontmatter allowlist (`Unexpected key(s) … argument-hint`); the `/` menu shows only `name` + `description`.
