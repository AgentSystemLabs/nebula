# Standing gotchas

The traps that outlive their task — a platform or tool quirk, a required ordering, a signal that lies, a
settled decision — one line each, in the TERMS.md section order, each line opening with the TERM it is
about. Read in full before every task; the RECALL HOOK also injects the matching lines. Written by the
NEBULA-MEMORY SKILL: durable gotchas are promoted here from their entry, a re-hit appends `· re-hit ×N date`,
and a line a test, type or GUARD HOOK rule now enforces is deleted. Each line ends with
`⟵ <entry file(s) in .claude/memory/entries/>`. Capped at 300 lines by `make memory-check`.

## The tree
- **PR ROW** — `gh pr view --json comments,reviews`: `comments[]` has `viewerDidAuthor`, `reviews[]` does not (needs `gh api user --jq .login`); inline review comments aren't a `--json` field at all — counting review submissions is the approximation. ⟵ 2026-08-23-pr-links-and-new-comment-counts · re-hit ×2 2026-08-30
- **PR ROW** — Both timestamps are RFC 3339 UTC and sort lexicographically, so `pr_seen` "newer than X" is a string compare with `""` as the sentinel — no `chrono`/`time` added to the deliberately dep-light workspace. ⟵ 2026-08-23-pr-links-and-new-comment-counts
- **PROJECT OPEN PRS GROUP** — Capture the cursor's PR before mutating `app.open_prs` and follow it by URL, not index — `gh pr list` is newest-first, so any new PR reshuffles every row below it. ⟵ 2026-08-24-retiring-closed-pull-requests-from-the-open-prs-group
- **PROJECT OPEN PRS GROUP** — `gh pr list --state open` includes drafts by construction — never "fix" a missing draft with a filter; the bug is downstream in `parse_list` or the `is_draft` badge. ⟵ 2026-08-24-retiring-closed-pull-requests-from-the-open-prs-group
- **PROJECT OPEN PRS GROUP** — PR rows must sort *after* the checkouts: `sel_worktree` indexes the combined list, so every `visible_worktrees().position(..)` stays right and `selected_worktree()` is `None` on a PR row. ⟵ 2026-08-24-open-pull-requests-under-the-worktrees-list
- **PROJECT OPEN PRS GROUP** — `restore_session` must not run when the cursor lands on a PR row — it detaches the terminal when `selected_worktree()` is `None`; guard both `move_selection` and the click handler. ⟵ 2026-08-24-open-pull-requests-under-the-worktrees-list
- **PROJECT OPEN PRS GROUP** — `gh pr list` returns a bare JSON array, not an object — `parse_list` takes `as_array()`, unlike `parse`. ⟵ 2026-08-24-open-pull-requests-under-the-worktrees-list
- **PROJECT OPEN PRS GROUP** — `Some(vec![])` (nothing open) and `None` (no `gh`, no remote, timeout) must stay distinct: `None` keeps the last good list on screen instead of blanking the group over one flaky round trip. ⟵ 2026-08-24-open-pull-requests-under-the-worktrees-list
- **ROOT WORKTREE** — `git rev-parse --show-toplevel` inside a linked worktree returns the worktree, not the repo; `git worktree list --porcelain` always lists the main checkout first and is the reliable root oracle. ⟵ 2026-08-25-the-root-row-named-after-a-worktree
- **ROOT WORKTREE** — git will swap a root's and a worktree's branches (`git switch --ignore-other-worktrees <wt-branch>` succeeds in the root), so a "wrong" ROOT BADGE can be reality — check `git worktree list` first. ⟵ 2026-08-25-the-root-row-named-after-a-worktree
- **STARTUP WORKSPACE** — `apply_startup_workspace` must run before `restore_ui_state` in the Snapshot arm: the restored project id only resolves against the workspace actually on screen. ⟵ 2026-08-24-workspaces-are-per-instance-not-daemon-global
- **TERMINAL SESSION** — The Aug 9 removal of terminals reads like a settled decision in the history and is not one (they came back) — don't cite it as precedent. ⟵ 2026-08-09-terminals-removed-then-brought-back
- **WORKSPACE** — `workspace = None` must survive for connections that never `Subscribe` — the one-shot `nebula add`, whose workspace genuinely is the current default; don't default it at connect time. ⟵ 2026-08-24-workspaces-are-per-instance-not-daemon-global
- **WORKSPACE** — A WORKSPACE is just a grouping of PROJECTS and the same PROJECT may belong to several — refusing to add a project already in another workspace was rejected by the user. ⟵ 2026-08-21-workspaces-and-the-o-t-e-hotkey-remap

## Processes and plumbing
- **ATTACH** — `app.term` and the daemon's attachment are two different things: tests setting `app.term = Some(AttachedTerm::new(…))` leave `attached_sref` unset, so `detach_if_attached` / `release_attachment` fall back to `term.sref` (a Detach the daemon holds nothing for is a no-op). ⟵ 2026-08-26-a-workspace-switch-cold-booted-a-fleet-of-claude-clis
- **ATTACH** — ATTACH is debounced after a selection move *only when the SESSION has no live PTY* (`preview_inner`'s `session_has_live_pty`, since 2026-08-30) — the wait exists to stop a passing cursor cold-spawning agent CLIs, not to save IPC; tests asserting an immediate `Attach` call `fire_pending_attach`; `reconcile_selection` / `jump_to_target` stay immediate (wrap them, they have early returns) and clicks go through `preview_selected_now`. ⟵ 2026-08-26-a-workspace-switch-cold-booted-a-fleet-of-claude-clis; 2026-08-30-walking-onto-a-live-session-attaches-without-the-debounce
- **ATTACH** — Input is dropped for a session the daemon hasn't spawned, so a pending attach must land before the first keystroke (`handle_terminal_event` fires it when `term_locked`; `Action::Activate` and `Action::Zoom` fire it too). ⟵ 2026-08-26-a-workspace-switch-cold-booted-a-fleet-of-claude-clis
- **ATTACH** — A kill-and-respawn under one `SessionRef` (Restart, WORKTREE RELOCATION, cloud re-entry) is invisible to the TUI — `attached_sref` dedups every re-attach and `SessionExited` only sets `exited` — so the daemon's forward task (`attach.rs::forward`) rebinds on `Daemon::session_installs`; a new spawn path must go through `install_session` or attached panes freeze until the user walks off the row and back. ⟵ 2026-09-04-a-respawn-behind-an-attached-pane-rebinds-the-client
- **DAEMON LOG** — DAEMON LOG records no hook traffic at `info` (`hook received` is `debug`; `hookEvent=` never appears), so the SQLITE STORE row (`claude_session_id` on `agents`) is the only cheap live oracle for status timing. ⟵ 2026-08-28-background-subagents-turned-the-session-green-idle-prompt-no
- **DAEMON SETSID** — Garbage tokens in the TUI were a shell job-control fight over the controlling terminal, not vt100: a new process group is not enough — a new session makes zsh's `/dev/tty` open fail so it skips job-control init. ⟵ 2026-08-20-the-daemon-needs-its-own-session-not-just-a-process-group
- **DATA DIR** — The real DATA DIR is `~/Library/Application Support/dev.nebula.nebula/` on macOS (`ProjectDirs::from("dev","nebula","nebula")`), `$XDG_DATA_HOME/nebula` on Linux; nothing prints it. ⟵ 2026-08-25-make-dev-showed-v0-4-0-and-no-projects
- **MIGRATION** — Migrations 2, 3, 7 and the migration-14 rebuild still spell out the divider columns and must — they already ran on every DB; only migration 18 drops them, so don't "tidy" old SQL. ⟵ 2026-08-25-project-dividers-removed-from-the-projects-column
- **PROTOCOL VERSION** — A PROTOCOL VERSION bump means the daemon still running from before the build refuses the new client until NEBULA KILL (or MAKE CYCLE) restarts it — expected; the client offers the kill-and-restart. ⟵ 2026-08-28-r-renames-a-project-row-without-touching-its-folder; 2026-08-28-released-v0-15-0-by-cherry-picking-only-the-post-v0-14-0-del
- **PTY SESSION** — Agent PTYs get `TERM=xterm-256color` (`pty/mod.rs`) but inherit the daemon's `TERM_PROGRAM`, so `/terminal-setup` inside nebula detects the terminal the daemon was first spawned from, not the one attached. ⟵ 2026-08-18-cmd-p-never-reaches-the-agent-in-terminal-app
- **RUNTIME DIR** — SUN_LEN is 104 bytes on macOS, so the dir holding the DAEMON SOCKET gets an 8-hex hash (`/tmp/nebula-dev-<8hex>/daemon.sock`), never the worktree name; use short dirs like `/tmp/nbws`. ⟵ 2026-08-26-one-nebula-per-checkout-auto-port-for-browser-per-path-dev-s; 2026-08-24-workspaces-are-per-instance-not-daemon-global · re-hit ×2 2026-09-04
- **SQLITE STORE** — A `COALESCE(workspace_id, ?1)` inside a shared `*_COLUMNS` const makes every query using it bind a hidden first parameter; rusqlite only checks bind counts, so a `WHERE workspace_id = ?1` would silently COALESCE NULL rows — select the bare column and apply `DEFAULT_WORKSPACE_ID` in `row_to_project`. ⟵ 2026-08-27-workspace-wide-dedup-pass-named-literals-shared-helpers-nebu
- **SQLITE STORE** — `sqlite3 ".backup"` reads the WAL, so the snapshot is consistent with the daemon still running; a plain `cp nebula.db` misses everything in `nebula.db-wal`. ⟵ 2026-08-25-make-dev-showed-v0-4-0-and-no-projects
- **VENDORED VT100** — VENDORED VT100 is 0.16.2 (`vendor/vt100/Cargo.toml`), not the 0.15.2 older entries claim, and there is no `resolve_editor` fn (it is `Config::editor` + `NEBULA_EDITOR`) — grep every symbol the log names before relying on it. ⟵ 2026-08-27-terms-md-one-all-caps-name-per-thing-kept-by-project-terms
- **VENDORED VT100** — Codex is a ratatui inline-viewport app scrolling inside a top-anchored DECSTBM region (`ESC[1;{viewport_top}r`); stock vt100 0.15.2 `grid.rs` `scroll_up` discards lines scrolled out of a region, so codex scrollback stayed empty. ⟵ 2026-08-14-vendored-vt100-so-codex-scrollback-works
- **VENDORED VT100** — `vendor/vt100` is a patched fork — do not upgrade or re-vendor it without re-applying the scroll-region patch. ⟵ 2026-08-14-vendored-vt100-so-codex-scrollback-works
- **VENDORED VT100** — Full-screen (alternate screen) apps are unaffected: that grid is created with zero scrollback capacity. ⟵ 2026-08-14-vendored-vt100-so-codex-scrollback-works
- **VERSION SKEW** — `nebula kill` is wrong advice when the *client* is older: the TUI respawns an identical daemon from `current_exe()`; `buildstamp_path()` is a content hash, not a path — pidfile + `ps` names the binary. ⟵ 2026-08-26-nebula-rename-broke-on-a-protocol-skew-the-error-message-mis · re-hit ×2 2026-08-28 · retire: `nebula rename` over the HOOK RECEIVER instead of the versioned socket
- **VERSION SKEW** — Do not add a field to `ServerEvent::Incompatible`: a newer daemon sends it to an older client and rmp is positional, so those clients fail to decode it ("unexpected handshake reply"). ⟵ 2026-08-26-nebula-rename-broke-on-a-protocol-skew-the-error-message-mis

## Layout — what is on screen
- **FLASH** — `app.flash` is cleared at the top of every key event (`handle_terminal_event`) before dispatch, so a flash set during a press survives exactly until the next key — a free one-shot hint. ⟵ 2026-08-27-a-double-tap-of-h-l-at-the-end-of-the-row-jumps-like-h-l
- **FOOTER** — The left edge is a fixed column budget already full — any addition shifts and clips everything downstream; a clipped FLASH is a broken feature (hence the flash-only yield), a clipped hint list is not. ⟵ 2026-08-24-the-version-nameplate-in-the-footer-s-left-edge
- **PILL ROW** — The "blank row" after the ROOT WORKTREE row / a group's last pill is that pill's un-overlapped bottom pad: `WorktreeEntry::height()` is `PILL_H + 1`, so `next_top - top` is 3 there and 2 when stacked. ⟵ 2026-08-27-the-root-worktree-row-s-lower-half-wasn-t-clickable
- **PILL ROW** — A cell holds one glyph and two colors, so the pad row's rail cell can't show panel-bg, rail and fill — no cleverer glyph exists; `draw_focus_tint` repaints only `bg == Color::Reset` cells. ⟵ 2026-08-24-black-notches-at-the-selected-pill-s-corners-issue-6
- **PR PREVIEW** — `schedule_pr_detail` zeroes `app.pr_preview_scroll` — never call it unconditionally from a timer path (the 60 s refresh yanked readers to the top); only where the row actually went away. ⟵ 2026-08-24-retiring-closed-pull-requests-from-the-open-prs-group
- **PR PREVIEW** — The pane reads `App::previewed_pr()`, whose SESSIONS PANEL half (the PR ROW) is keyed on `Focus::Sessions` on purpose — a session is still ATTACHED behind that pane, so focusing it must bring the terminal back; notice "the pane reads something else" at `note_preview_change` (URL diff after the burst drains), never per `sel_session =` write. ⟵ 2026-08-28 the-sessions-panel-s-pr-row-reads-in-the-pr-preview-too
- **PR PREVIEW** — `draw_terminal` returning early on a PR row is the whole trick — the ATTACH underneath stays live, so walking into the group and back never churns; do not "clear" the terminal for it. ⟵ 2026-08-24-reading-a-pull-request-and-its-diff-inside-nebula
- **PR PREVIEW** — `gh pr view --json`: comments carry `createdAt`, reviews `submittedAt` + `state`; a review with no `submittedAt` is your own pending draft — drop it. ⟵ 2026-08-24-reading-a-pull-request-and-its-diff-inside-nebula
- **PR PREVIEW** — `split_unified_diff` takes the path from `+++ b/…` and falls back to the `diff --git` header: a deleted file's `+++` is `/dev/null` and a rename's two halves differ. ⟵ 2026-08-24-reading-a-pull-request-and-its-diff-inside-nebula
- **RECENCY ORDER** — Archived sessions count toward a worktree's / project's AGO BADGE stamp (archiving is housekeeping, not activity), so a worktree whose only session is archived still says `5m ago` over an empty SESSIONS PANEL — deliberate. ⟵ 2026-08-28-lists-order-themselves-move-project-removed-projects-and-wor
- **ROW BADGES** — Panel columns are fixed width (`DEFAULT_PANEL_WIDTHS[1]` = 22 for the WORKTREES PANEL), so a wider badge clips instead of reflowing (` 1 done` produced `root 1 don`); widening the TESTBACKEND changes only the TERMINAL PANE. ⟵ 2026-08-27-done-reads-violet-and-says-done; 2026-08-28-lists-order-themselves-move-project-removed-projects-and-wor
- **SPLASH** — `Tree::has_visible_projects()` is deliberately workspace-scoped (panel hints, `Action::New`, the splash's own line) — only the splash gate got the DEFAULT WORKSPACE condition; don't fold it in. ⟵ 2026-08-25-the-splash-is-scoped-to-the-default-workspace
- **TAB UNDERLINE** — Box-drawing line glyphs never touch a cell edge; block elements (`▀`/`▄`) do — any "join two rows of fill" problem in this TUI is a block-element problem, not a heavier-line problem. ⟵ 2026-08-27-the-open-tab-s-underline-was-a-half-cell-away-from-the-tab
- **TAB UNDERLINE** — Judging a sub-cell glyph needs a real font raster: Pillow + `/System/Library/Fonts/Menlo.ttc` at ~27px drawing the candidate cell stacks side by side — no demo daemon, no tmux. ⟵ 2026-08-27-the-open-tab-s-underline-was-a-half-cell-away-from-the-tab
- **TAB UNDERLINE** — The accent underline deliberately sits slightly above the `─` edge rule beside it (mid-cell vs top-of-cell) — the tab indicator reads heavier than the divider; not a misalignment to fix. ⟵ 2026-08-27-the-open-tab-s-underline-was-a-half-cell-away-from-the-tab

## Status and badges
- **DONE BADGE** — "Done" means read-vs-unread (`Agent::unseen`), not finished-vs-not — settled after two wrong readings; when a color is asked for "so it's obvious something needs addressing", use the flag that already means it. ⟵ 2026-08-27-done-reads-violet-and-says-done
- **DONE BADGE** — The counter is daemon-side, in the SQL `CASE` of `set_agent_status`, not `AgentStatusMachine` (which dedups unchanged statuses); NEEDS FEEDBACK → FINISHED counts, FRESH → FINISHED does not. ⟵ 2026-08-26-unwatched-finishes-count-on-the-project-and-worktree-rows
- **PROGRESS SCANNER** — Esc-cancelling a Claude turn fires no hook at all: `Stop` skips user interrupts and `idle_prompt` needs 60s quiet AND no keyboard touch (Claude Code 2.1.241: only `UserPromptSubmit` then `SessionEnd` fired). ⟵ 2026-08-23-cancelling-claude-left-the-status-stuck
- **PROGRESS SCANNER** — The window title is unusable as a busy/idle signal — during a permission prompt it shows idle (`✳`) while OSC 9;4 correctly stays busy (`3`); trust the progress state, never the title. ⟵ 2026-08-23-cancelling-claude-left-the-status-stuck
- **PROGRESS SCANNER** — Codex and cursor-agent emit no OSC 9;4 at all, so the progress path is inert for them. ⟵ 2026-08-23-cancelling-claude-left-the-status-stuck
- **ROOT BADGE** — The ROOT BADGE yields to a branch it would otherwise truncate (`● main 1 done`, never `● ma… ⌂ root 1 done`) — the ⌂ is decoration, the branch is the row's identity. ⟵ 2026-08-27-done-reads-violet-and-says-done
- **STATUS DOT** — "Green" in this user's prompts is the `forest` THEME's *accent* (`Indexed(114)`, `~/.nebula-dev/config.json`), not `th.ok` — check the config's `theme` before grepping for `ok`; the cursor's rail and the TAB UNDERLINE now take `status_color(..)` (lifted dim→muted via `selection_mark`), so only a dot-less row is still accent. ⟵ 2026-08-28-the-selection-rail-and-tab-underline-take-the-status-dot-color
- **STATUS MACHINE** — `SessionEnded` only flips AGENT STATUS from RUNNING/NEEDS FEEDBACK, so a row that dies at FRESH (a failed cloud create) stays gray — the CLOUD BADGE and `alive:false` are the only tells. ⟵ 2026-08-26-cloud-rows-re-enter-their-session-on-restart
- **STOP GATE** — `TaskStop`-killing a BACKGROUND SUBAGENT delivers no `SubagentStop` (a normal completion does) — that orphan stays yellow up to the 30 min QUIET GRACE; expect "stuck on yellow" reports. ⟵ 2026-08-28-background-subagents-turned-the-session-green-idle-prompt-no
- **STOP GATE** — Subagent tool traffic reaches the STATUS MACHINE only for hooked tools (`PostToolUse` `Bash|EnterWorktree|ExitWorktree`, `AskUserQuestion`): a Read/Grep-only worker shows life only at start and stop, so the quiet clock must stay generous. ⟵ 2026-08-28-background-subagents-turned-the-session-green-idle-prompt-no
- **STOP GATE** — The quiet clock counts from the last sign of life, not from the held Stop — a test written "from the hold" is off by the SubagentStart→Stop gap. ⟵ 2026-08-28-background-subagents-turned-the-session-green-idle-prompt-no

## Focus, navigation and keys
- **CLICK OUTSIDE** — One `Down(Left)` pre-check at the top of `handle_mouse` covers all fourteen modals and what each unwinds on the way out lives in `overlay_close::click_outside` — never re-add a per-variant hit-test; it needs `area.width > 0` (an undrawn overlay has a zero rect, so every click would read as outside), so a test wanting the outside path draws once with TESTBACKEND (`drawn_modal_area`). ⟵ 2026-08-27-click-outside-any-modal-dismisses-it; 2026-08-30-every-modal-closes-on-ctrl-q-a-click-outside-or-one-esc
- **DOUBLE TAP** — "Double tap" means double tap: the single `h`/`l` press at the WALK EDGE must stay a no-op and only the pair jumps — implement the gesture, not the state it implies. ⟵ 2026-08-27-a-double-tap-of-h-l-at-the-end-of-the-row-jumps-like-h-l
- **DOUBLE TAP** — 50 ms is not a human double tap (~120–250 ms), so the window is the app's `DOUBLE_CLICK` (400 ms); held-key auto-repeat (~90 ms on macOS) still spills, and `REPORT_EVENT_TYPES` (→ `KeyEventKind::Repeat`) was deliberately not added since it changes what every terminal sends. ⟵ 2026-08-27-a-double-tap-of-h-l-at-the-end-of-the-row-jumps-like-h-l
- **DOUBLE TAP** — `app.flash` is cleared per terminal event (`handle_terminal_event`), not per `handle_key`, so the test `press()` helper leaves the last "`x` again: …" hint standing — set `app.flash = None` before asserting `flash.is_none()`. ⟵ 2026-08-28-k-k-and-j-j-double-tap-between-the-panels-and-the-workspaces-bar
- **DOUBLE TAP** — `k` on row 0 of any panel (an empty panel counts) arms the top-edge DOUBLE TAP while the WORKSPACES BAR is shown, so a test wanting a "neutral" key press should use `j` or an unbound key. ⟵ 2026-08-28-k-k-and-j-j-double-tap-between-the-panels-and-the-workspaces-bar
- **DRAG SELECT** — "Shift+drag selects text" is a lie in Terminal.app — there is no mouse-reporting bypass there, unlike Ghostty/iTerm. ⟵ 2026-08-04-the-focus-key-odyssey-ctrl-q
- **ESCAPE HATCH** — Ctrl+Q is settled — don't relitigate: Cmd+arrows (no kitty), Ctrl+arrows (Mission Control), Ctrl+Esc/Option+Esc (undeliverable), Ctrl+] (feel), double-Esc (Claude owns Esc), Shift+arrows/Ctrl+G/T (Claude binds them) all lost. ⟵ 2026-08-04-the-focus-key-odyssey-ctrl-q
- **ESCAPE HATCH** — crossterm collapses a same-read `\x1b\x1b` pair into one Esc event (escaped-escape rule), which is what made double-Esc unworkable. ⟵ 2026-08-04-the-focus-key-odyssey-ctrl-q
- **FOCUS** — Nothing on a create's *launch* path touches `app.focus`: the `ServerEvent::Ack` arm is where a new SESSION enters and locks the TERMINAL PANE, so a launch surface that wants to stay out of the way flips `AgentLaunchDraft::focus_pane` → `PendingIntent::AttachCreated { focus }` / `AttachCreatedWithCloudRetry { focus, .. }` (the QUICK PROMPT is the *WithCloudRetry* one — it reopens on error, not because it is cloud). ⟵ 2026-08-29-a-quick-prompt-launch-no-longer-steals-the-terminal-pane
- **FOCUS** — The event loop's `if app.focus != focus_before` at the end of each iteration is the one choke point for "focus changed" — there are ~135 `app.focus = Focus::…` assignments; hook there, not per assignment. ⟵ 2026-08-28-pull-requests-refresh-every-15-s-and-on-focus-not-once-a-min
- **KEYMAP** — The TUI runs in raw mode, so `Ctrl+C` arrives as a `KeyEvent`, never SIGINT: whatever gates the quit ACTION is the *only* way out, and must keep a `Ctrl+C` escape of its own (the HARDWIRED UNLOCK argument). ⟵ 2026-08-29-q-asks-before-it-quits-the-tui
- **KEYMAP** — Never bulk-replace `Char('h')`/`Char('l')` in `event_loop.rs` — most hits are overlay-local grammar (settings cycling, diff and tree browsers) the KEYMAP doesn't own. ⟵ 2026-08-24-h-l-move-between-panels-issue-8
- **KEYMAP** — FOOTER and HELP OVERLAY hints come from `Keymap::first(action)`, so the CHORD you want displayed must lead the `defaults:` list (`["h", "left"]` shows `h`, `["left", "h"]` shows `←`). ⟵ 2026-08-24-h-l-move-between-panels-issue-8
- **KEYMAP** — Terminal.app never encodes Cmd into pty bytes (⌘P arrives as Option+P's `π`) and fails the kitty probe, so Cmd-modified keys and Ctrl+Esc never reach the app there; the ⌘P remedy is `/model`, or `ctrl+p` → `chat:modelPicker` in `~/.claude/keybindings.json`. ⟵ 2026-08-18-cmd-p-never-reaches-the-agent-in-terminal-app; 2026-08-04-the-focus-key-odyssey-ctrl-q
